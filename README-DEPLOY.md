# تحديثات تلقائية عبر GitHub — الفرات الحلوة (Hostinger)

هذا المستودع = **الكود فقط**. لا بيانات منتجات حيّة، ولا عملاء، ولا إعدادات قاعدة، ولا مفاتيح —
كل ذلك يبقى داخل سيرفر المالك وحده (`public_html/data/`)، والسكربت هنا لا يلمسه.

## كيف يشتغل النظام
1. المصمم يعدّل الكود → `git push` إلى هذا المستودع.
2. مهمة Cron على Hostinger كل 10 دقائق تشغّل `deploy/furat-deploy.sh`.
3. السكربت: لو فيه جديد → يسحبه ويطبّق ملفات الكود فوق `public_html` (استخراج، بدون حذف).
   لو لا جديد → لا يكتب ولا سطر. **ملفات `data/` على السيرفر خارج العملية كلها.**

## التركيب مرة واحدة (الفني — عبر SSH من cPanel/Hostinger)
```bash
# 1) عدّل رابط المستودع في السطر المخصص (سطر واحد فقط)
nano ~/public_html/../furat-setup.env 2>/dev/null || true
# أو حرر مباشرة بعد أول استنساخ يدوي:
git clone https://github.com/FerasFuad34/furat-push.git ~/furat-src
nano ~/furat-src/deploy/furat-deploy.sh   # عدّل REPO_URL الافتراضي (اختياري — أو صدّره بيئيًا)

# 2) شغّله يدويًا مرة للتأكد (يطابق ما سيفعله cron)
export FURAT_REPO_URL="https://github.com/FerasFuad34/furat-push.git"
bash ~/furat-src/deploy/furat-deploy.sh
```

### إضافة المهمة في Hostinger
لوحة hPanel ← «CRON Jobs» ← مهمة جديدة كل 10 دقائق:
```
*\/10 * * * *   FURAT_REPO_URL="رابط-مستودعكم" bash $HOME/furat-src/deploy/furat-deploy.sh >> $HOME/furat-deploy.log 2>&1
```
(بعض لوحات Hostinger تعرض الحقول منفصلة: دقيقة `*/10` والساعة `*` … والأمر بدون نجوم.)

## الضمانات المدمجة
- **الحارس المزدوج:** `.gitignore` يمنع تتبع `data/*.json` وdb-config والنسخ — ولو أضاف أحدُهم ملف بيانات بالخطأ، السكربت يطبع تحذيرًا في اللوغ ولا ينسخه فوق سيرفر حيّ (ملفات غير متتبَّعة لا تدخل الاستخراج أصلًا).
- **لا حذف في السيرفر:** السكربت يستخرج الملفات الجديدة فوق الموجود — ما يحذف أي ملف موجود على الاستضافة.
- **قفل ضد التراكض** + خروج صامت لو ما فيه جديد + اللوغ في `~/furat-deploy.log`.
- **لو تعطّل GitHub:** لا شيء يتأثر — الموقع يشتغل محليًا؛ السكربت يعيد المحاولة في الدورية التالية.

## ملاحظة أمان (اتفاق التسليم)
- المستودع عام أو خاص — لا فرق: لا توجد فيه أي معلومة سرية.
- مفتاح الـ Token المستخدم للدفع: صلاحية «مستودع واحد، قراءة/كتابة فقط»، ويُحذف ويُستبدل بعد كل دفعة تسليم من إعدادات GitHub ← Developer settings.
- `install.php`: السكربت يحذفه تلقائيًا من السيرفر بعد كل مزامنة إذا كان التركيب مكتملًا (يوجد `db-config.json` أو `data.json` حقيقي) — فلا يعود يظهَر للفني شبح المثبّت بعد اختفائه.
